## 1. 产品定位与核心价值

一款深度融合 AI Agent 能力的健身训练伴侣 App。

**一句话定位**：训练中全程不用碰手机——语音交互记录训练、AI 动态调整音乐、练后自动获得分析与建议。

**核心差异化**（相对传统健身 App）：

| 维度     | 传统健身 App | 本产品                   |
| -------- | ------------ | ------------------------ |
| 训练计划 | 模板化       | AI 基于个人数据动态生成  |
| 训练记录 | 手动点选     | 语音一句话记录           |
| 音乐     | 手动选歌单   | Agent 按训练阶段实时决策 |
| 交互     | 触屏         | 语音为主 + 触屏辅助      |

## 2. 用户画像

### 2.1 主力画像：进阶训练者「老张」

- **背景**：32 岁，互联网从业者，系统训练 2 年+，每周 3-4 练，以力量训练为主（深蹲/卧推/硬拉）
- **训练习惯**：戴耳机听歌训练；组间休息刷手机；用备忘录或纸笔零散记录重量
- **痛点**：
  1. 记组打断节奏——每组后解锁手机、切 App、点选输入，组间休息被切碎
  2. 平台期不知道怎么调整——重量卡了 2 个月，现有 App 只展示图表不给判断
  3. 歌单听腻了，训练中切歌打断状态
- **付费意愿**：为「省麻烦 + 真有效」付费，对订阅制不排斥
- **设备**：iPhone + AirPods，训练时手机放一旁

### 2.2 次级画像：系统化进阶者「小李」

- **背景**：26 岁，健身 8 个月，动作已掌握但无计划概念，跟着视频练
- **痛点**：不知道怎么安排一周训练；想知道自己有没有进步
- **价值点**：AI 生成计划 + 练后成果分析（"过去 4 周下肢容量增长 12%"）

### 2.3 暂不服务的人群

| 人群              | 原因                                            |
| ----------------- | ----------------------------------------------- |
| 纯新手            | 需要动作教学视频/真人指导，语音交互无法覆盖     |
| 不戴耳机训练者    | 语音 I/O 与音乐体验依赖耳机，外放场景嘈杂不可用 |
| 团体课/有氧操用户 | 以团课跟练为主，无组间结构，Agent 模型不匹配    |

## 3. 核心使用场景

按优先级排序（详细技术流程见 architecture.md 第 17 章）：

| #   | 场景           | 用户故事                                                     | 涉及能力                    |
| --- | -------------- | ------------------------------------------------------------ | --------------------------- |
| S1  | 练前规划       | 作为训练者，我说"帮我排本周计划"，得到符合我器械与目标的计划 | Planner Agent               |
| S2  | 训练中语音记录 | 我说"深蹲 100 公斤 5 次"，App 确认"已记录"，全程不碰手机     | ASR + VoiceIntent + 本地TTS |
| S3  | 训练中音乐跟随 | 进入力竭组时音乐自动变炸；我说"换歌"立即生效                 | DJ Agent + EventBus         |
| S4  | 练后分析建议   | 训练结束自动收到成果解读与下次建议                           | Analysis + Suggestion       |
| S5  | FM 主播陪伴    | 训练中有 AI 主播解说、激励、播报成果                         | FM Host Agent               |
| S6  | 情绪感知       | App 从我语气判断疲劳，自动调整建议与音乐                     | VoiceFeedbackAgent          |

## 4. MVP 边界

### 4.1 MVP 定义

> **用户用一次完整的力量训练验证核心价值：练前拿到 AI 计划 → 训练中全程语音记录 + 音乐自动跟随 → 练后收到分析。**

覆盖场景 **S1 + S2 + S3（简化版）+ S4（简化版）**，对应技术路线图的垂直切片，而非按 Phase 1→7 逐层建设。

### 4.2 In Scope（MVP 包含）

| 模块     | 范围                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 训练计划 | Planner Agent 生成周计划（云端 LLM + JSON Schema 校验）                               |
| 语音记录 | "重量+次数"句式识别（LogSetIntent），快捷短语：停/加一组/换歌                         |
| 语音反馈 | 本地 TTS 即时确认（预合成优先）                                                       |
| ASR      | 本地 Whisper.cpp base；仅 Passive + 按钮主动模式，无唤醒词                            |
| 音乐     | MusicCurator 静态歌单（按训练阶段 BPM 曲线）+ DJ **规则路径**（力竭组/跳歌/循环信号） |
| 音频     | MVP 混音方案：双播放器实例 + 手动音量包络 ducking                                     |
| 分析建议 | Analysis Agent 练后总结 + 规则版建议（SafetyGuard 硬规则先行，无 Multi-Agent）        |
| 数据     | 本地 SQLite 全量；event_log 事件溯源                                                  |
| 隐私     | 录音指示红点、麦克风一键关闭、语音记录可删除                                          |

### 4.3 Out of Scope（MVP 明确不做）

| 不做项                   | 原因                                     | 后续阶段  |
| ------------------------ | ---------------------------------------- | --------- |
| 唤醒词 "Hey Coach"       | 持续唤醒的工程与耗电复杂，按钮触发已可用 | Phase 5   |
| FM Host 主播             | 依赖云端 TTS + 混音引擎，非核心闭环      | Phase 4/6 |
| VoiceFeedback 副语言分析 | 差异化亮点但非闭环必需                   | Phase 6   |
| DJ LLM 路径              | 规则路径已覆盖 80% 信号场景              | Phase 6   |
| Multi-Agent Suggestion   | 先用规则版建议 + SafetyGuard 验证价值    | Phase 2   |
| 云端 ASR/TTS 增强        | 本地优先，验证后再加                     | Phase 7   |
| 原生混音引擎             | MVP 用双实例方案                         | Phase 6   |
| 音乐版权规模化           | MVP 用免版税曲库                         | 成长期    |

### 4.4 MVP 成功标准（北极星 + 护栏）

- **北极星指标**：周人均「语音记录组数」（核心价值动作的直接度量）
- **激活指标**：新用户 7 日内完成 ≥ 1 次全程语音记录的训练
- **留存指标**：4 周留存 ≥ 30%（健身 App 基准约 20-25%）
- **护栏指标**：语音记录误识率 < 5%；端到端语音反馈 ≤ 2.5s；因 TTS/音乐打断导致的训练中止率 < 2%

## 5. 成功指标（全量产品）

| 层级   | 指标                             | 目标      |
| ------ | -------------------------------- | --------- |
| 北极星 | 周人均语音记录组数               | ≥ 40      |
| 激活   | 7 日内完成首次全程语音训练       | ≥ 60%     |
| 留存   | 4 周 / 12 周留存                 | 30% / 15% |
| 深度   | 周人均训练次数                   | ≥ 2.5     |
| 质量   | 建议采纳率（用户按计划执行比例） | ≥ 70%     |
| 体验   | 语音交互端到端 P90 延迟          | ≤ 2.5s    |

## 6. 验收标准（MVP 关键路径）

| #   | 验收项       | 标准                                                          |
| --- | ------------ | ------------------------------------------------------------- |
| A1  | 计划生成     | 输入画像后 ≤ 5s 输出可解析周计划；伤病动作必被替换或加注      |
| A2  | 语音记录     | 安静健身房环境下"深蹲 100 公斤 5 次"类句式识别准确率 ≥ 95%    |
| A3  | 语音反馈延迟 | 说完到 TTS 确认出声，P90 ≤ 2.5s；预合成命中 ≤ 100ms           |
| A4  | 音乐跟随     | 力竭组（RPE≥9）信号后 200ms 内完成切歌决策；跳歌即时生效      |
| A5  | 打断与恢复   | 语音确认不打断音乐节奏（ducking 后恢复）；说"停"立即中止播报  |
| A6  | 安全兜底     | recovery_score < 2 时建议必为 rest/deload（SafetyGuard 拦截） |
| A7  | 离线可用     | 飞行模式下可完成：语音记录 + 本地歌单播放 + 本地 TTS          |
| A8  | 隐私         | 原始音频不落盘；录音有红点指示；语音记录可一键清空            |

## 7. 非目标（Non-Goals）

- 不做社交/社区/排行榜
- 不做饮食记录与营养计划
- 不做动作视频教学（新手引导）
- 不做智能硬件（手表端、心率带）接入——MVP 后评估
- 不承诺医疗建议，所有训练建议附免责声明
